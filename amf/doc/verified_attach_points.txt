SUMMARY
--------------------------------------------------------------------------
- 40/40 distinct symbols cited across the PDF's 23 states + Part 3 are present
  in bin/amf, confirmed via `nm` + DWARF-resolved source lines via
  `go tool objdump -s`.
- bin/amf's DWARF line numbers match the PDF closely (usually exact; small
  1-20 line offsets occur where the PDF cites a multi-line function signature
  vs. DWARF citing the first body instruction -- not a wrong symbol).
- Two entries needed clarification, not correction:
    * internal/gmm.Authentication -- PDF's line 222 is a switch-branch inside
      the function, whose body actually starts at sm.go:150.
    * context.(*AmfUe).SecurityContextIsValid -- PDF's "gmm/sm.go:272" is the
      call site inside SecurityMode, not the function's own definition
      (context/amf_ue.go:468).
- ue.MacFailed (state 16) has no symbol, as expected -- it's a struct field,
  not a function; PDF correctly flags it [DERIVED].
- free5gc/util/fsm.(*FSM).SendEvent (Part 3) IS resolvable in the static
  binary, confirming the PDF's note that it's hookable via `go tool nm`.
- These verified func_name strings are ready to drop into new attach_target
  arrays in amf_functions.c (currently #if 0'd sections cover the old,
  unrelated processor-layer probes -- see amf/missing_attach_points.txt).
